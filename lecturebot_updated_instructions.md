# LectureBot --- інструкція та вимоги до PoC-проєкту

## 1. Назва проєкту

**Створення Telegram-бота для генерації конспектів і тестів із
відеолекцій із використанням Telegram Bot API, YouTube Data API v3,
Google Cloud Speech-to-Text API, Google Cloud Storage та Gemini API
(Vertex AI).**

Коротка назва: **LectureBot**.

## 2. Мета проєкту

Розробити прототип Telegram-бота, який допомагає студентам швидше
опрацьовувати навчальні відео. Користувач надсилає боту аудіозапис,
голосове повідомлення, коротке відео або посилання на YouTube-лекцію, а
система отримує текст лекції та за ним генерує структурований конспект і
тест для самоперевірки.

Проєкт має продемонструвати інтеграцію зовнішніх API, взаємодію
компонентів хмарної системи Google Cloud та практичне застосування
генеративного ШІ.

## 3. Проблема та цільова аудиторія

### Проблема

Навчальні відео часто тривають десятки хвилин або кілька годин.
Студентам потрібно витрачати час на перегляд, нотатки та підготовку до
перевірки знань. Якщо готових субтитрів немає, вручну створювати
конспект ще складніше.

### Цільові користувачі

-   студенти університетів і коледжів;
-   учні, які використовують відеоматеріали для підготовки;
-   викладачі, яким потрібно швидко підготувати запитання за лекцією;
-   люди, які навчаються самостійно за відеокурсами;
-   автори онлайн-курсів, яким потрібні конспекти й тести до своїх відео.

## 4. Основні сценарії використання

1.  **Аудіофайл або голосове повідомлення.** Користувач надсилає
    аудіозапис лекції (до 20 МБ). Система транскрибує його через
    Speech-to-Text.
2.  **Короткий відеофайл.** Користувач надсилає відео (до 20 МБ). Система
    витягує аудіодоріжку через FFmpeg і транскрибує її.
3.  **Відео з YouTube.** Користувач надсилає посилання на публічне відео.
    Бот отримує метадані через YouTube Data API v3 (назва, канал,
    тривалість, статус доступу), показує картку підтвердження, а потім
    передає посилання безпосередньо в Gemini, який офіційно підтримує
    обробку публічних YouTube-відео.
4.  **Конспект.** Бот створює стислий структурований конспект із
    заголовками, ключовими поняттями та основними висновками.
5.  **Тест.** Бот формує запитання з варіантами відповідей, правильними
    відповідями та поясненнями й надсилає їх як нативні
    **Telegram-вікторини** (quiz polls).
6.  **Питання за лекцією.** Користувач може поставити запитання, а бот
    відповідає на основі отриманого транскрипту.

Для мінімального PoC достатньо сценаріїв 1, 2, 4, 5. Сценарії 3 і 6 є
додатковими, але реалізуються без складних обхідних рішень.

## 5. API та призначення кожного

### 5.1. Telegram Bot API

**Призначення:** інтерфейс користувача й обмін повідомленнями.

Використання:

-   отримання повідомлень і файлів від користувача;
-   обробка команд і натискань inline-кнопок;
-   надсилання конспектів, повідомлень про статус і тестів;
-   тести у форматі нативних вікторин: `sendPoll` з `type="quiz"`,
    `correct_option_id` та `explanation`.

Приклади команд:

-   `/start` --- початок роботи;
-   `/help` --- інструкція та попередження про приватність;
-   `/new` --- обробити нову лекцію (скидає поточний транскрипт).

**Важливі обмеження:**

-   Бот через стандартний (хмарний) Bot API може **завантажити файл
    розміром не більше 20 МБ**. Тому основний сценарій --- аудіо, голосові
    повідомлення та короткі відео. Користувачу варто радити надсилати
    стиснуте аудіо (20 МБ у MP3/Opus --- це приблизно 40--80 хвилин
    мовлення). Більші файли бот відхиляє з підказкою.
-   Довжина текстового повідомлення --- до 4096 символів. Довгий конспект
    розбивається на частини або додатково надсилається файлом
    `summary.md`.
-   Ліміти вікторини: запитання --- до 300 символів, варіант відповіді ---
    до 100, пояснення --- до 200. Ці ліміти передаються Gemini у промпті.
-   Бот не має доступу до історії довільних каналів; для PoC користувач
    пересилає повідомлення або завантажує файл напряму.

Бібліотека: **python-telegram-bot** (v21+, асинхронна, підтримує polling
і webhook).

Документація: https://core.telegram.org/bots/api

### 5.2. YouTube Data API v3

**Призначення:** отримання та перевірка метаданих відео за посиланням.

Використання:

-   витягування ідентифікатора відео з посилань виду `watch?v=`,
    `youtu.be/`, `shorts/`;
-   виклик `videos.list` (`part=snippet,contentDetails,status`): назва,
    канал, тривалість, статус приватності;
-   показ картки підтвердження користувачу;
-   перевірка, що відео публічне та не довше встановленого ліміту
    (наприклад, 1 година), до того як витрачати ресурси Gemini.

**Важливо:** YouTube Data API v3 не надає аудіо відео, а метод
`captions.download` працює лише для відео, власником яких є автор
запиту. Тому сам вміст відео обробляє Gemini, який офіційно приймає
посилання на публічне YouTube-відео як вхідні дані (одне відео на
запит). Бот нічого не завантажує з YouTube і не обходить обмеження
платформи.

Документація:

-   https://developers.google.com/youtube/v3
-   https://developers.google.com/youtube/v3/docs/videos/list
-   https://developers.google.com/youtube/terms/api-services-terms-of-service

### 5.3. Google Cloud Speech-to-Text API

**Призначення:** автоматичне перетворення мовлення з аудіо на текст.

Типовий потік:

1.  Користувач надсилає аудіо або відео.
2.  FFmpeg конвертує файл у FLAC, моно, 16 кГц (для відео ---
    витягує аудіодоріжку).
3.  Якщо запис коротший за ~55 секунд --- синхронний виклик
    `recognize`.
4.  Якщо довший --- файл завантажується в Cloud Storage, і виконується
    асинхронний `long_running_recognize` з `gs://`-посиланням
    (синхронне розпізнавання підтримує лише до 1 хвилини аудіо).
5.  Параметри: `language_code="uk-UA"`,
    `alternative_language_codes=["en-US"]`,
    `enable_automatic_punctuation=True`.
6.  Результат перевіряється на порожній транскрипт і передається до
    Gemini; тимчасовий файл у Cloud Storage видаляється.

Безкоштовно: 60 хвилин розпізнавання на місяць, далі оплата за
секунди аудіо (у межах Free Trial --- з кредитів).

Документація: https://cloud.google.com/speech-to-text/docs

### 5.4. Google Cloud Storage

**Призначення:** тимчасове зберігання аудіо для асинхронного
розпізнавання довгих записів.

-   окремий бакет, регіон `us-central1`, публічний доступ заборонено;
-   правило життєвого циклу: автоматичне видалення об'єктів через 1 день;
-   бот видаляє файл одразу після транскрибування.

Документація: https://cloud.google.com/storage/docs

### 5.5. Gemini API (через Vertex AI)

**Призначення:** генерація навчальних матеріалів на основі транскрипту
або YouTube-відео.

Vertex AI у консолі Google Cloud тепер називається **Gemini Enterprise
Agent Platform**; API для ввімкнення --- Vertex AI API.

Спосіб доступу: SDK `google-genai` (`enterprise=True`) --- оплата з
кредитів Free Trial, та сама автентифікація, що й для Speech-to-Text і
Cloud Storage. Резервний варіант --- API-ключ із Google AI Studio
(перемикається змінною середовища). Назва моделі задається змінною
`GEMINI_MODEL` (обрати актуальну модель Flash у консолі).

Використання:

-   створення структурованого конспекту;
-   виділення ключових термінів і визначень;
-   генерація тестів у форматі JSON за схемою (`response_schema` +
    Pydantic-модель), а не просто «попросити JSON»;
-   обробка YouTube-відео за посиланням;
-   відповіді на запитання користувача за матеріалом лекції.

Рекомендований підхід:

-   явно вказувати, що відповідь має спиратися лише на наданий
    транскрипт;
-   не дозволяти моделі вигадувати відсутні факти;
-   валідувати відповідь моделі (Pydantic) перед надсиланням;
-   для довгих лекцій розбивати текст на фрагменти, узагальнювати їх, а
    потім формувати загальний конспект (map-reduce).

Формат тестового запитання: запитання; чотири варіанти відповіді;
індекс правильної відповіді; коротке пояснення (≤ 200 символів).

Документація:

-   https://cloud.google.com/vertex-ai/generative-ai/docs
-   https://ai.google.dev/gemini-api/docs

## 7. Технологічний стек

-   **Мова:** Python 3.11+.
-   **Telegram:** `python-telegram-bot` v21+.
-   **Speech-to-Text:** `google-cloud-speech`.
-   **Cloud Storage:** `google-cloud-storage`.
-   **Gemini:** `google-genai` (режим Vertex AI).
-   **YouTube:** `google-api-python-client`.
-   **Валідація:** `pydantic`.
-   **Відео/аудіо:** FFmpeg.
-   **Конфігурація:** змінні середовища, локально --- файл `.env`
    (`python-dotenv`).
-   **Тести:** `pytest`.
-   **Хостинг:** розробка й демонстрація --- локально (polling).
    Опційно --- Cloud Run у режимі webhook з параметрами
    `--no-cpu-throttling --min-instances=1 --max-instances=1` (щоб
    фонова обробка не зупинялася), секрети --- у Secret Manager.
    Розгортати ближче до захисту, щоб не витрачати кредити.
-   **GitHub:** код, README та інструкція запуску.

База даних для PoC не потрібна: транскрипт зберігається в пам'яті
сесії користувача (`context.user_data`) до команди `/new`.

## 9. Вимоги до зручності користування (UX)

1.  **Простий старт:** після `/start` --- коротке пояснення й кнопка
    «Обробити лекцію».
2.  **Зрозумілі джерела:** бот повідомляє, що можна надіслати аудіо,
    голосове, відео до 20 МБ або YouTube-посилання.
3.  **Прогрес:** одне повідомлення статусу, яке оновлюється.
4.  **Вибір результату:** після транскрибування --- кнопки «Конспект»,
    «Тест», «Обидва», «Поставити запитання».
5.  **Тест:** нативні Telegram-вікторини з поясненням правильної
    відповіді.
6.  **Обробка помилок:** файл завеликий, формат не підтримується,
    мовлення не розпізнано, відео приватне чи задовге, API недоступний
    або вичерпано квоту.
7.  **Приватність:** у `/help` пояснити, що файли обробляються
    сервісами Google; тимчасові файли видаляються одразу після
    обробки.
8.  **Межі результату:** попереджати, що автоматично створений конспект
    і тест можуть містити помилки.

## 10. Нефункціональні вимоги та безпека

-   Ключі зберігати у змінних середовища (локально) або Secret Manager
    (Cloud Run).
-   Локально використовувати Application Default Credentials
    (`gcloud auth application-default login`), а не JSON-ключі
    сервісного акаунта.
-   `.env` --- у `.gitignore`; у репозиторії лише `.env.example`.
-   API-ключ YouTube обмежити лише YouTube Data API v3.
-   Перевіряти тип і розмір файлу до завантаження.
-   Обмежувати довжину транскрипту та розмір запитів до Gemini.
-   Блокуючі виклики Google API виконувати в окремому потоці
    (`asyncio.to_thread`), щоб бот не «зависав» для інших користувачів.
-   Не логувати секрети та повні транскрипти.
-   Налаштувати бюджет і сповіщення в Google Cloud Billing.
-   Для демонстрації використовувати матеріали, на обробку яких є права
    (власний запис або відео з ліцензією Creative Commons).

## 11. Free Trial Google Cloud і вартість

-   Нові акаунти отримують **$300 кредитів на 90 днів**. Картка потрібна
    лише для верифікації; списань не буде, доки вручну не перейти на
    платний акаунт.
-   Speech-to-Text: 60 хв/міс безкоштовно, далі --- з кредитів.
-   Cloud Storage: 5 ГБ безкоштовно в регіонах US; файли видаляються
    автоматично.
-   Gemini (Vertex AI): оплата за токени з кредитів; для PoC --- центи.
-   YouTube Data API v3: безкоштовно, квота 10 000 одиниць/день
    (`videos.list` = 1 одиниця).
-   Cloud Run з `min-instances=1` і постійним CPU коштує кілька доларів на
    тиждень --- вмикати лише на період демонстрації.
-   Обов'язково: Billing → Budgets & alerts → бюджет $10 зі
    сповіщеннями.

## 12. План реалізації PoC

### Етап 1. Підготовка (вручну)

-   Активувати Free Trial, створити проєкт, увімкнути API, створити
    бакет, ключ YouTube, токен Telegram (див. розділ 18).
-   Встановити Python, Git, FFmpeg, gcloud CLI.
-   Створити GitHub-репозиторій.

### Етап 2. Каркас і Telegram-інтерфейс

-   Структура проєкту, `requirements.txt`, `config.py`.
-   `/start`, `/help`, `/new`, inline-кнопки; запуск у режимі polling.
-   Приймання аудіо/голосових/відео/документів, перевірка розміру.

### Етап 3. Транскрибування

-   Конвертація через FFmpeg.
-   Синхронне розпізнавання для коротких записів, Cloud Storage +
    асинхронне для довгих.
-   Збереження транскрипту в сесії користувача.

### Етап 4. Генерація матеріалів

-   Конспект (з розбиттям на частини для Telegram).
-   Тест за JSON-схемою → валідація → Telegram-вікторини.
-   Запитання й відповіді за транскриптом.

### Етап 5. YouTube

-   Витягування video ID, `videos.list`, картка підтвердження.
-   Перевірка статусу й тривалості; обробка через Gemini.

### Етап 6. Тестування

-   Unit-тести: розбір посилань, тривалості ISO 8601, валідація схеми,
    розбиття тексту.
-   Ручні сценарії: голосове 30 с, MP3 5 хв, коротке MP4, файл > 20 МБ,
    тиша, публічне та приватне YouTube-відео.
-   Перевірити, що бакет порожній після обробки, а в репозиторії немає
    секретів.

### Етап 7. Деплой і демонстрація

-   Опційно: `Dockerfile` → `gcloud run deploy --source .`, webhook.
-   Записати демо-відео, підготувати презентацію, оформити README.

## 13. План демонстрації

Рекомендована тривалість: 2--4 хвилини.

1.  Показати `/start` і меню бота.
2.  Надіслати заздалегідь підготовлений аудіофайл лекції (2--5 хв).
3.  Показати оновлення статусу обробки.
4.  Показати конспект.
5.  Пройти 1--2 запитання тесту у вигляді Telegram-вікторини.
6.  Поставити запитання за лекцією.
7.  Надіслати YouTube-посилання: картка з метаданими → конспект.
8.  Завершити схемою архітектури та посиланням на GitHub.

Не покладатися на те, що довга лекція обробиться миттєво; мати запасне
відео з демонстрацією.

## 16. Як пояснити проєкт на презентації

**Проблема:** студентам складно швидко опрацьовувати довгі відеолекції
та готуватися до перевірки знань.

**Рішення:** Telegram-бот перетворює аудіо лекції на текст за допомогою
Google Cloud Speech-to-Text (довгі записи --- через Cloud Storage), а
Gemini на Vertex AI створює конспект і тест, який проходиться прямо в
Telegram. Для YouTube-лекцій YouTube Data API v3 перевіряє відео, а
Gemini обробляє його за посиланням.

**Чому це корисно:** бот скорочує час на первинне опрацювання матеріалу
й допомагає перевірити розуміння лекції.

**Основні обмеження:** файли до 20 МБ (ліміт Telegram Bot API); лише
публічні YouTube-відео; якість результату залежить від якості звуку;
згенеровані матеріали потребують перевірки.

## 18. Що зробити вручну (налаштування сервісів)

1.  **Free Trial:** https://cloud.google.com/free → «Get started for
    free» → вхід через Google → дані картки (лише верифікація).
2.  **Проєкт:** https://console.cloud.google.com → вибір проєкту → New
    project `lecturebot`. Записати **Project ID**.
3.  **Бюджет:** Billing → Budgets & alerts → Create budget, $10,
    сповіщення 50/90/100 %.
4.  **Увімкнути API** (APIs & Services → Library): Cloud Speech-to-Text
    API, Cloud Storage (увімкнено за замовчуванням), Vertex AI API,
    YouTube Data API v3. Для деплою пізніше: Cloud Run Admin API, Cloud
    Build API, Artifact Registry API, Secret Manager API.
5.  **Ключ YouTube:** APIs & Services → Credentials → Create credentials
    → API key → Restrict key → API restrictions: лише YouTube Data API
    v3. → `YOUTUBE_API_KEY`.
6.  **Бакет:** Cloud Storage → Buckets → Create: назва
    `lecturebot-audio-<project-id>`, регіон `us-central1`, клас Standard,
    uniform access, Public access prevention увімкнено. Вкладка Lifecycle
    → правило «Delete object», вік 1 день. → `GCS_BUCKET`.
7.  **Локальна автентифікація:** встановити gcloud CLI
    (https://cloud.google.com/sdk/docs/install), виконати:
    `gcloud init`, `gcloud auth application-default login`,
    `gcloud auth application-default set-quota-project <PROJECT_ID>`.
8.  **Сервісний акаунт (для Cloud Run):** IAM & Admin → Service accounts
    → `lecturebot-sa` з ролями Cloud Speech Client, Vertex AI User,
    Storage Object Admin, Secret Manager Secret Accessor. JSON-ключ не
    завантажувати без потреби.
9.  **Gemini:** у Vertex AI → Model Garden обрати доступну модель Gemini
    Flash → `GEMINI_MODEL`, регіон → `GOOGLE_CLOUD_LOCATION`
    (`us-central1` або `global`). Резерв: https://aistudio.google.com →
    Get API key → обрати свій проєкт → `GEMINI_API_KEY`.
10. **Telegram:** @BotFather → `/newbot` → назва та username із
    закінченням `bot` → токен → `TELEGRAM_BOT_TOKEN`. Далі
    `/setcommands` (start, help, new) і `/setdescription`.
11. **Інструменти:** Python 3.11+, Git, FFmpeg
    (`winget install Gyan.FFmpeg`, перевірка `ffmpeg -version`),
    GitHub-акаунт і публічний репозиторій `lecturebot`.
12. **Демо-матеріали:** власний запис лекції на 2--5 хв або матеріал із
    ліцензією CC; одне публічне YouTube-відео з ліцензією CC.
13. **`.env`:** заповнити за зразком `.env.example` (не комітити).
